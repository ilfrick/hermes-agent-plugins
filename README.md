# Ollama Memory Provider

**Local-first semantic memory for Hermes Agent using Ollama embeddings.**

Stores facts, preferences, and conversation context in a SQLite database with vector embeddings generated by a local Ollama model (default: `qwen3-embedding:4b`). No cloud services, no external APIs — everything runs on your LAN.

---

## Features

- **Semantic search** — find relevant memories by meaning, not keywords
- **Local embeddings** — uses your Ollama instance (`qwen3-embedding:4b` or any compatible model)
- **SQLite storage** — portable, no separate vector DB required
- **Auto-mirror** — optionally mirrors built-in `memory.add`/`memory.replace` writes
- **Tool integration** — `ollama_search`, `ollama_remember`, `ollama_forget`, `ollama_status`, `ollama_reindex`
- **Multiplex-safe** — profile-scoped database, works with `hermes multiplex`
- **Zero config default** — works out of the box with `http://192.168.10.20:11434`

## Installation

The plugin is installed in your Hermes home:

```
$HERMES_HOME/plugins/ollama_memory/
├── __init__.py          # Provider implementation
├── config_schema.py     # Dashboard config schema
├── plugin.yaml          # Plugin metadata
└── README.md            # This file
```

No Python dependencies beyond stdlib + `requests` (already in Hermes).

**Prerequisite**: Ollama running with an embedding model:

```bash
# On your Ollama host (192.168.10.20)
ollama pull qwen3-embedding:4b
# or any model that supports /api/embeddings
```

## Configuration

Add to `config.yaml` under `memory.ollama_memory`:

```yaml
memory:
  provider: ollama_memory
  ollama_memory:
    endpoint: "http://192.168.10.20:11434"   # Ollama API base URL
    model: "qwen3-embedding:4b"              # Embedding model name
    collection: "hermes_memory"              # Logical collection / table suffix
    top_k: 8                                 # Default search results
    similarity_threshold: 0.25               # Cosine similarity cutoff (0-1)
    max_context_tokens: 1200                 # Max tokens in prefetch context
    auto_embed_writes: true                  # Mirror built-in memory writes
```

Or configure via the **Dashboard → Memory → Ollama Local Embeddings** panel.

### Field Reference

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `endpoint` | string | `http://192.168.10.20:11434` | Ollama API base URL (protocol + host + port) |
| `model` | string | `qwen3-embedding:4b` | Embedding model name (must be pulled on Ollama host) |
| `collection` | string | `hermes_memory` | Table suffix; changing creates a new isolated store |
| `top_k` | integer | `8` | Default number of search results |
| `similarity_threshold` | number | `0.25` | Cosine similarity cutoff (0–1) |
| `max_context_tokens` | integer | `1200` | Token budget for prefetch context block |
| `auto_embed_writes` | boolean | `true` | Mirror `memory.add`/`replace` to Ollama store |

## Activation

```bash
# Set as active memory provider
hermes config set memory.provider ollama_memory

# Restart gateway to load the provider
hermes gateway restart
```

Verify it's active:

```bash
hermes chat -q "Use ollama_status to check the memory provider"
```

Expected output includes:
```json

  "model": "qwen3-embedding:4b",
  "collection": "hermes_memory",
```

## Usage

### Tools (available to the agent)

| Tool | Purpose | Parameters |
|------|---------|------------|
| `ollama_search` | Semantic search | `query` (string, required), `top_k` (int, optional) |
| `ollama_remember` | Store a fact | `content` (string, required), `memory_type` (enum, optional), `importance` (0–1, optional) |
| `ollama_forget` | Delete by ID | `memory_id` (int, required) |
| `ollama_status` | Provider health & stats | — |
| `ollama_reindex` | Rebuild all embeddings | — |

### Examples

**Store a fact:**
```json
{
  "tool": "ollama_remember",
  "arguments": {
    "content": "Nicola prefers concise responses under 200 words",
    "memory_type": "preference",
    "importance": 0.9
  }
}
```

**Search memories:**
```json
{
  "tool": "ollama_search",
  "arguments": {
    "query": "Nicola response length preference",
    "top_k": 5
  }
}
```

**Check status:**
```json
{
  "tool": "ollama_status",
  "arguments": {}
}
```

**Reindex after model change:**
```json
{
  "tool": "ollama_reindex",
  "arguments": {}
}
```

## How It Works

1. **Initialization**: On gateway start, provider connects to Ollama, creates/opens `~/.hermes/ollama_memory.db`
2. **Embedding**: Text → Ollama `/api/embeddings` → 2560-dim vector (for `qwen3-embedding:4b`)
3. **Storage**: Content + embedding + metadata stored in SQLite table `memories_<collection>`
4. **Search**: Query embedded → cosine similarity against stored vectors → top-K filtered by threshold
5. **Prefetch**: At each turn start, user query is embedded and searched; results injected as context block
6. **Sync**: Each conversation turn (user + assistant) is embedded and stored as `memory_type: "conversation"`
7. **Mirror**: Built-in `memory.add`/`replace` calls are also embedded if `auto_embed_writes: true`

### Database Schema

```sql
CREATE TABLE memories_<collection> (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    content TEXT NOT NULL,
    embedding BLOB NOT NULL,           -- JSON array of floats
    memory_type TEXT DEFAULT 'factual',
    importance REAL DEFAULT 0.7,
    metadata JSON DEFAULT '{}',
    created_at TEXT NOT NULL,          -- ISO 8601 UTC
    updated_at TEXT NOT NULL
);
```

Indexes on `memory_type` and `created_at` for filtered scans.

## Performance Notes

- **Scan-based search**: No FAISS/Annoy; linear scan capped at 5000 most recent rows
- **Good for**: < 10k memories (typical personal use)
- **Embedding latency**: ~50–200ms per call on LAN Ollama
- **Reindex**: Sequential; allow minutes for thousands of memories

For larger scale, consider adding FAISS or pgvector via a fork.

## Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| `available: false` | Ollama unreachable | Check `endpoint`, firewall, `ollama serve` |
| `embedding dimension mismatch` | Model changed | Run `ollama_reindex` or change `collection` |
| `No relevant memories found` | Threshold too high | Lower `similarity_threshold` (try 0.15) |
| Slow search | Too many memories | Increase threshold, reduce `top_k` |
| Duplicate memories | Multiple `remember` calls | Use `ollama_forget` + re-add, or accept duplicates |

## Migration from File Memory

If you previously used file-based memory (`MEMORY.md`, `USER.md`), the provider does **not** auto-import them. To migrate:

```bash
# 1. Export current memory (if using a tool that supports it)
# 2. Use ollama_remember for each fact you want to keep
# 3. Or write a one-off script to batch-import from MEMORY.md
```

## Uninstall / Disable

```bash
# Switch back to file memory
hermes config set memory.provider ""

# Or disable plugin (keeps config, removes from active providers)
hermes plugins disable ollama_memory

# Restart gateway
hermes gateway restart
```

Database file remains at `~/.hermes/ollama_memory.db` (or profile-specific path).
